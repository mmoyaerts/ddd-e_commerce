# Repositories métier

## CommandeRepository

| Opération métier                       | Description                                                                                                                                                                                                                                                                                                               | Contraintes / règles métier                                                                                                                                                                                      |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Créer une commande                     | Permet d’enregistrer une nouvelle commande initiée par un client après validation du panier. La commande est créée avec un statut initial (ex : "créée") et contient les lignes de commande, l’adresse de livraison et les informations associées. Cette opération déclenche généralement des événements métier comme *CommandeCréée*. | Une commande doit contenir au moins une ligne valide. Les produits doivent être disponibles en stock au moment de la création. L’adresse de livraison doit être complète et valide.                              |
| Obtenir une commande                   | Permet de récupérer une commande à partir de son identifiant unique. Cette opération est utilisée pour afficher les détails au client ou pour traitement interne. Elle garantit un accès cohérent à l’état courant de la commande.                                                                                                     | L’identifiant doit exister. L’accès peut être restreint selon le rôle (client ou opérateur). Les données retournées doivent refléter un état cohérent.                                                           |
| Mettre à jour le statut de la commande | Permet de faire évoluer l’état de la commande dans son cycle de vie (payée, préparée, expédiée, livrée). Cette opération est déclenchée par des événements provenant d’autres contextes (paiement, préparation, livraison). Elle garantit la traçabilité du processus.                                                                 | Les transitions de statut doivent respecter le cycle métier défini. Une commande payée ne peut pas revenir à l’état initial. Certaines transitions nécessitent des événements préalables (ex : paiement validé). |
| Annuler une commande                   | Permet d’annuler une commande avant son expédition. Cette opération peut être déclenchée par le client ou le système (ex : paiement échoué). Elle met à jour le statut et peut déclencher un remboursement.                                                                                                                            | Une commande déjà expédiée ne peut pas être annulée. Si le paiement est validé, un remboursement doit être initié. Les stocks doivent être réajustés après annulation.                                           |

## LivraisonRepository

| Opération métier                     | Description                                                                                                                                                                                                                            | Contraintes / règles métier                                                                                                                                                               |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Créer une livraison                  | Permet de créer une livraison à partir d’une commande préparée. Cette opération enregistre les informations du colis, du transporteur et de l’adresse de livraison. Elle initie le processus d’expédition et génère un identifiant de suivi.        | La commande doit exister et être au statut "préparée". L’adresse de livraison doit être valide. Un identifiant de suivi unique doit être généré.                                          |
| Obtenir une livraison                | Permet de consulter les détails d’une livraison via son identifiant ou son numéro de suivi. Cette opération est utilisée par le client et les opérateurs pour suivre l’acheminement. Elle expose les statuts et les événements liés à la livraison. | La livraison doit exister. Les informations doivent être synchronisées avec le transporteur. L’accès peut être limité selon les rôles.                                                    |
| Mettre à jour le statut de livraison | Permet de modifier l’état de la livraison (expédiée, en cours, livrée, échouée). Cette opération est généralement déclenchée par le transporteur ou un événement externe. Elle garantit un suivi fiable pour le client.                             | Les transitions doivent respecter le cycle métier. Les mises à jour doivent être horodatées. Les statuts doivent être cohérents avec les événements réels du transporteur.                |
